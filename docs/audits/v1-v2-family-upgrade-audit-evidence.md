## ground:sync-plane  `(a5579eb62135073e2)`

**Confidence:** high

**Notes:** SLICE 2 — same-user private-DB DeviceSync zone under mixed V1 (CKQuery coordinator) / V2 (CKSyncEngine) versions. Bridge schema-awareness is CONFIRMED shipped in tag v1.31.2 (absent in v1.31.1), so the "V2 profiles read-only on V1" contract is real and largely holds via field-level preservation on both sides. The interop is far safer than a naive read would suggest: SyncedProfile/SyncedLocation/ProfileSession record types are shared and field-compatible, both engines preserve unknown fields on write, and the schema gate protects V2 trigger data. RELEASE-BLOCKING RISK CONCENTRATES IN RESET, not steady-state edit/delete: V2's reset issues a full deleteZone(DeviceSync) that wipes all of a V1 device's records in the shared zone, and V1 reacts to a zoneNotFound by early-returning (skipping deletion reconciliation) then re-pushing its local profiles — resurrecting them into the freshly-reset zone and diverging from V2's seeded state. Secondary risks: (a) V1 hard-deletes V2's fixed-name reset command record after processing it, potentially starving other V2 devices of the command; (b) concurrent V1-edit + V2-delete resurrects a server record that V2's local-only tombstone cannot re-delete, so a second V2 device recreates the profile; (c) a V1 reset never deletes V2-only Emergency* records (V1 doesn't know those types) so they survive a V1-issued reset. No crashes from unknown record types — V1's per-recordType CKQuery simply never fetches V2-only types, and V2's apply switch has a default no-op. All claims cited by branch:file.
