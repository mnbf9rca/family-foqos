- Apple's [TN3208](https://developer.apple.com/documentation/technotes/tn3208-preparing-your-apps-launch-screen-to-meet-app-store-requirements) says uploads built with iOS 27 SDK need one of `UILaunchStoryboardName`, `UILaunchStoryboards`, `UILaunchScreen`, `UILaunchScreens` in the app plist. Generated SwiftUI configuration may already satisfy this; verify the product.
- Apple's [compatibility-key documentation](https://developer.apple.com/documentation/bundleresources/information-property-list/uidesignrequirescompatibility) says the key is ignored for iOS 27 builds. Fix demonstrated usability/accessibility defects instead of adding an opt-out.
- The [official runner image inventory](https://github.com/actions/runner-images) lists `xcode-27`; its [image document](https://github.com/actions/runner-images/blob/main/images/macos/xcode-27-arm64-Readme.md) lists Xcode 27.0 / 27A266a at `/Applications/Xcode_27.app`, macOS 27 and iOS 27 SDKs. Recheck actual label availability, account access, image status and CodeQL Swift extraction at S3 execution; local release status does not settle hosted service support.
- Epic claims about static-link default changes and isolation regressions are hypotheses to test. No local compile/link/test failure was reproduced during planning. No tools, package linkage, OS defaults, entitlements or simulator registry were changed.
