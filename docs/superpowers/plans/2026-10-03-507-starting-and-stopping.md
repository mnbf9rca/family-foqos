# V2 starting and stopping implementation plan — slice 2

> **For agentic workers:** Use `superpowers:executing-plans` to implement task-by-task in build1's assigned feature worktree. Steps use checkbox syntax. The Herdr reviewer supplies independent review; do not create a second implementation fleet.

**Goal:** Every admitted originating V2 start establishes its configured countdown before activation, and Same stops use the session's synced initiating identity.

**Architecture:** Extend the existing shared snapshots, timer registrar/activity and session CAS rather than introducing another strategy hierarchy. Extract the foundations' configuration validation into FoqosShared so the app and monitor enforce one admission contract. Separate originating creation from authoritative adoption; adoption never registers a timer.

**Tech stack:** Swift, SwiftUI, SwiftData, FoqosShared, DeviceActivity, app-group locking, private DeviceSync CloudKit.

**Spec:** [Approved rulebook](../specs/2026-10-02-508-v2-conditions-rulebook.md), including its later rulings; [#507 human comments](https://github.com/mnbf9rca/family-foqos/issues/507) and [#521 human comments](https://github.com/mnbf9rca/family-foqos/issues/521). Baseline `origin/main` = `52fb651f964637e5f8ae82815a866f92b606c7d5`, foundations PR #526.

## Global constraints

- R1: V2 start and stop conditions are independent and combine freely. No pairing logic and no reuse of V1 strategy behaviour.
- Duration is an integer in `DeviceActivityLimits.minimumIntervalMinutes...maximumTimerMinutes` (15...1439). No silent default/clamping; selected Timer without a valid V1 duration is inert, and needs another operational stop.
- Only an interactive Manual start can adjust duration, only when `allowChangingTimerBeforeStart` is on. Child may adjust even a locked profile. All other origins use the saved duration; obsolete Shortcut Duration is refused.
- Preserve selection, Screen Time, mode, profile-edit lock and applicable geofence checks. Timer expiry bypasses geofence/background veto. No emergency-stop fallback counts toward admission.
- Private-account session sync only; no FamilyPolicies session/tag payload. Genuine active V1 sessions keep bounded V1 handling and conversion deferral. No unreleased-V2 hydration, compatibility repair or telemetry.
- All changed copy must use the approved strings below. Existing unrelated authorization/error copy remains. No source work on the planner branch.
- Use separate assigned worktree, credential warm-up dispatched by orchestrator, new signed commits, no amend/force. Every simulator command uses `--agent build1 --session collab`; only orchestrator grants reservations/merges after the specific human gate.

## Scope and stopping point

Implements #509/#510, session-origin/mirror and existing in-app Same matching for #512, #513's predicate removal, and #493's common originating admission. #509 is release-blocking: converted Shortcut-timer profiles must obtain their saved countdown rather than depend on Emergency Unblock.

Slice 3 (#514) removes the background-stop flag and all remaining veto/status consumers. Slice 4 (#515–#517) replaces paired schedule intervals, removes foreground catch-up, fixes recurrence validation/late callbacks/stop precedence and V1 schedule leakage. Slice 5 (#521) supplies verified background metadata, typed payload producers/readers, namespace conversion at scan boundaries, R10 switching and removes Link stop authority. This slice must enforce its admission/registration contract in the existing schedule and URL adapters now, but does not claim those later adapters' complete product semantics. Schedule-only admission counts a valid configured recurrence independently of the old flag; its actual veto is removed in slice 3. Existing invalidity from the foundations' paired schedule rules remains until slice 4.

Never claim #507 or #512's complete new written-tag/background acceptance finished here. Slice 5 finishes that delivery integration. All #507 slices and their actual-device release evidence must finish before the V2 App Store release.

## Review focus

1. Monitor/app race between registration and publication must cancel the candidate, preserving the winning session and restrictions (Task 2).
2. A stale same-profile timer or queued stop must never terminate its replacement, including after CAS refetch (Tasks 2/4).
3. Invalid converted/synced profiles and inert missing-duration V1 Timers must receive the correct refusal before effects on every real adapter (Tasks 1/3).
4. Mirrors with missing identity must retain blocking state and deny Same, while an identified mirror can stop and propagate completion without timer ownership (Task 4).
5. Cancelled Manual adjustment or locked Child adjustment must preserve the saved duration and never start prematurely (Task 3).

## Task 2: Establish a countdown before publishing any originating session

**Files:** shared/app creation, StrategyTimerActivity, TimerActivityUtil, DeviceActivityCenterUtil, StrategyManager; SessionTimerEnd/StrategyTimerActivity/SharedData identity and scheduled-end tests.

**Interfaces:** `StrategyTimerActivity.register(profileId: UUID, sessionId: String, minutes: Int, now: Date) throws -> Date` is the shared OS registrar. App `DeviceActivityCenterUtil.registerStrategyTimer` delegates and accepts the same session identity. Activity format is `StrategyTimerActivity:<profile UUID>:<session UUID>`; strict parse, no unknown three-part name fallback to a schedule. Existing two-part V1 timer names are supported only for genuinely active unmigrated V1 lifecycle. Keep other timer dispatch formats unchanged. `removeStrategyTimerActivity(profileId: UUID, sessionId: String)` cancels exactly that activity.

Add `SharedData.commitOriginatingSession(_ candidate: SessionSnapshot, expectedVictimId: String?, now: Date) -> Bool`: under `withLockStatus`, fail on lock/encoding/write/readback error or changed ownership. Snapshot carries candidate ID, origin and accepted deadline. Stage encoded outgoing-completion/candidate data before modifying shared state; preserve previous values on failure. End victim/publish candidate atomically for competing app/extension users of that same lock. Activation/deactivation effects requiring ownership run in the same guarded transition, rather than a later unguarded global deactivation. Reuse current locking/commit machinery; no second store or distributed transaction framework.

App originating creation becomes a throwing prepare/save/commit path: allocate ID without appending to `profile.sessions`; admit, register provisional Timer if operational, construct/insert session, `context.save()`, ownership-guarded shared commit, then restrictions/UI/live activity/sync. Never `context.rollback()` unrelated edits. Do not call the old effectful `createSession`/Manual strategy for V2 creation. Keep restoration/adoption and genuine V1 paths separate and version-gated. A cross-process lock must also guard the current authoritative session check; nil victims mean idle is required, not permission to overwrite.
