# One tag concept implementation plan — slice 5

> **For agentic workers:** Use `superpowers:executing-plans` in build1's assigned worktree with the existing Herdr reviewer. Checkbox steps track work. Planner changes only this plan.

**Goal:** A verified NFC/QR event has the same identity and configured start/stop behavior in-app or in the background, with safe profile switching and no separate Link stop.

**Architecture:** One validated profile-link parser and one typed scan event feed the existing StrategyManager. Retain raw UID/QR digest projections for genuine V1 callers; V2 uses typed identities and the slice-2 originating transaction. A small pending-switch value keeps A's exact session, target B and original B event through required-key confirmation.

**Tech stack:** Swift, Foundation URLComponents, CoreNFC, NSUserActivity/CoreImage barcode descriptors, existing CodeScanner/CoreImage QR generator, SwiftData, FoqosShared and private DeviceSync.

**Spec:** [#508 rulebook](../specs/2026-10-02-508-v2-conditions-rulebook.md), R10/B9/B10/N8 and approved G7/verified-route/legacy decisions; [#521 comments](https://github.com/mnbf9rca/family-foqos/issues/521), including mandatory scheme/host validation; [slice 2](2026-10-03-507-starting-and-stopping.md), [slice 3](2026-10-03-507-remove-background-stop-safeguard.md), [slice 4](2026-10-03-507-independent-schedules.md). Implements #521 and completes #512's verified background identity integration. Research baseline `52fb651`; implement atop merged earlier slices/build2 presentation work.

## Global constraints

- Tag type plus short random opaque key identifies new app-written NFC/generated QR payloads at `https://family-foqos.app/profile/<UUID>/<nfc-or-qr>/<random>`. Distinct logical tags/codes get distinct keys; reusing/sharing that payload retains its key. Profile UUID is never the key, and copied payloads match as the same key without claiming physical authenticity.
- Accept profile commands only from HTTPS and the exact universal-link host `family-foqos.app`, with valid exact path fields/type/usable key. No custom scheme for profile commands. Malformed identified paths never downgrade to permissive legacy links.
- Successful legacy app-written no-ID in-app reads retain uppercase NFC UID (`%02hhX`) or normalized/raw QR digests. Existing unnamespaced keys remain valid. Non-app NFC uses UID; non-profile QR keeps digest compatibility. NFC read error is C15/retry, never UID fallback/enrollment. Successful no-NDEF is distinct from an error.
- Background NFC is verified only by recognized URI NDEF record (well-known U or absolute URI) matching webpageURL. Empty-format sentinel/nonzero record count is not proof. System QR needs a nonnil QR barcode descriptor. Other URL opens, including third-party scanners and Shortcut Open URL, are ordinary Link, regardless of suffix/referrer/claimed type.
- Verified type disagreeing with typed payload refuses C22 before effects. Legacy untyped background event counts Any only of the verified initiating route's type; Specific is never inferred. Same becomes Any-of-that-type only for an explicitly recorded, admitted unidentified legacy-tag session. Missing mirror origin never means Any.
- Targeted B admits through Link OR matching NFC/QR start in both routes. Ordinary Link requires Link and idle; it never stops/switches any active profile. An explicit Start on P ignores any embedded B and checks only P's selected tag start. Confirmation keeps pending B and never changes B's initiating event to A's proof.
- Target active A is stop-only: use configured A stops, never A start admission or new countdown. A targetless scan can end A but cannot invent B. No hidden repair, automatic key/entrance addition, force-start bypass or unreleased-V2 Link-only grandfathering.
- Prepare B admission/countdown and obtain A stop/geofence authorization before committing the exact-session transition. Cancellation, read failure, wrong proof, B rejection/registration failure and ownership race leave A intact. Preserve existing Screen Time/selection/mode/lock rules; no extra Child start-adjustment restriction.
- Private-account tag/session sync only. Preserve genuine active V1 behavior/conversion deferral and older V1 readers; no destructive #59 retirement. Use approved copy below verbatim, existing surfaces and buttons. No secrets, full opaque keys or personal identifiers in logs.
- Agent drives all simulator UI checks with throwaway uncommitted tests, owner `build1`, session `collab`. Actual NFC/Camera/Code Scanner metadata delivery requires devices as specified below. Signed commits; no amend/force, unreserved writes or Production schema promotion.

## Review focus

1. A typed URL alone must never manufacture background scan proof; wrong domain/custom scheme/route disagreement must fail before session effects (Task 1).
2. Actual generated/written payloads must round-trip as the same typed key in both readers while legacy UID/digest matches survive (Task 2).
3. Confirmation of A's required key must preserve target B and B's original key, including cancellation/replacement races (Task 3).
4. Active A's own tag must end once without re-starting A or establishing another timer (Task 3).

## Task 1: Validated link/event boundary and delivery classification

**Files:** ProfileTagLink, NavigationManager, FoqosApp, scanners, PhysicalReader, Home and parser tests.

**Interfaces:** In one helper file, `ParsedProfileLink` carries profile UUID and optional typed type/key; `TagEvent` carries NFC/QR type, namespace/key (or explicit verified unidentified legacy state), optional target UUID and existing QR raw-digest alternative. `ProfileTagLink.parse(_ url: URL) throws -> ParsedProfileLink` accepts the exact two-segment legacy shape or four-segment identified shape, never partial extra/missing components or encoded path traversal. Use URLComponents; HTTPS host validation rejects other hosts, userinfo and alternate/custom schemes. Passive navigation remains separate from session commands. Generated key is a lower-case UUID-derived 32-hex string; recognized typed payloads require that usable shape and matching type.

`ProfileTagLink.classify(_ activity: NSUserActivity) -> Delivery` distinguishes verified NFC, verified QR and ordinary Link by metadata, then checks typed payload agreement. `.onOpenURL` is ordinary Link. Preserve userActivity through FoqosApp/NavigationManager instead of retaining only webpageURL/profileId. Explicitly route custom SceneDelegate cold `connectionOptions.userActivities` and warm `scene(_:continue:)` browsing-web activities into this same classifier; preserve CloudKit share routing separately. Forward cold `connectionOptions.urlContexts` and warm `scene(_:openURLContexts:)` as ordinary Link. Because AppDelegate explicitly installs SceneDelegate, use that layer as the sole command consumer for its scene: While SceneDelegate is installed, SwiftUI `.onContinueUserActivity`/`.onOpenURL` never execute commands. Make this an explicit scene-ownership gate rather than correlating URLs across the two layers. The SceneDelegate is the sole command executor for its scene and sends both activity and URL-context deliveries through the common classifier/dispatcher. Register scene ownership before cold options are forwarded. Keep a per-activity consumed token only in memory to suppress replay of the same activity within the owning path; no persistent URL blacklist or time debounce, and distinct later taps with identical payloads remain legitimate events. This also avoids mistaking the URL-only copy of a verified activity for a separate ordinary Link command. Multiple metadata proofs must agree on type; conflicting proof fails, never downgrades. A new delivery can be consumed once without stale fields in NavigationManager. Update FoqosApp’s existing URL-log redaction to mask profile UUID and opaque path key; query/fragment-only redaction currently exposes both. Do not log event payloads or use display placeholders as identifiers.

NFCResult retains current `id` UID for V1 plus optional canonical event for V2. QRScanResult retains current `hash`/`rawHash` for V1 plus optional canonical event/target for V2; widen callback error type only as needed to deliver approved parser errors through the existing scanner surface. PhysicalReader/editor V2 enrollment selects the canonical event's key; genuine V1 callers use raw members. No separate parser in each scanner.
