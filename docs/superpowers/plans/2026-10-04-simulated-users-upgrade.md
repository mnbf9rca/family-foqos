# Simulated Users Upgrade Implementation Plan

> **For build1:** Use superpowers:executing-plans task by task; this approved plan travels in the implementation PR. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Observe realistic V1 users updating to V2, then using the app through its actual UI, with inspected screenshots and a verdict for every persona on iOS 26.5 and iOS 27.

**Architecture:** Reuse the V1 seed data and owned-simulator backup/capture helper. An external XCUITest runner drives a persistent V1 app, then the V2 app installed over it; the application never hosts these tests. Checked-in fixture patches reproduce the unavailable simulator boundaries in disposable worktrees; a flag-gated Debug report supplements only facts invisible in the UI.

**Tech stack:** SwiftData/UserDefaults, XCUITest, existing `FoqosScreenshots` UI target, Python standard library, `simctl`, and the normal simulator gate.

**Spec:** This assignment and its diagnostic-report addition; [upgrade runbook](../../v1-v2-upgrade-runbook.md), [UI verification](../../simulator-ui-verification.md), and [V2 rulebook](../specs/2026-10-02-508-v2-conditions-rulebook.md) supply procedure and expected behavior.

## Constraints and evidence

- Pin `origin/release/v1` to the existing 1.31.3 source `589bee9` and resolve the requested current V2 head before running; record exact commits, installed versions/builds, runtime, UUID, locale/timezone, and substitutions.
- Use each assigned agent’s normal `<agent>/collab` owner; the orchestrator assigns runs across owners actually running 26.5 and 27. Record `IOS_SIM_GATE_RUNTIME_VERSION`; never borrow another owner or treat one runtime as both.
- Use a disposable application with fresh V1 state per persona and runtime; keep the previous application/group backup and every failed attempt. Never uninstall, clear preferences, substitute a V2 store, or reseed between the V1 capture and V2 journey.
- No hosted `FoqosTests` execution in this upgrade procedure. [Apple forum 805060](https://developer.apple.com/forums/thread/805060) reports simulator runner hangs and an uninstall workaround; the reported local install-over hang is the reason for the external runner, and uninstall would destroy our acceptance premise.
- Use normal persisted containers and production startup/migration/action paths. `--screenshot-demo` creates an in-memory store and is forbidden here. No pre-migration by the driver, direct start/stop API calls from tests, or forced success/error dismissal.
- Confine simulator substitutions to unavailable boundaries: authorization/app-selection prerequisites, restrictions, CloudKit transport/lock-record responses, hardware scan delivery, and DeviceActivity registration/delivery. Label each substituted boundary; preserve real mode, lock verification, migration, routing, validation, persistence, and UI decisions.
- Diagnostic reports compile entirely out of Release, require `--upgrade-diagnostics`, and neither import XCTest nor detect/inject a hosted test runtime. The personas contain only synthetic data: reports may include synthetic profile names, settings, keys and full session details needed by the checks. Never run persona seeding/report collection against a real user’s store; ordinary logging rules still apply.
- Emergency state follows the [recorded human ruling](https://github.com/mnbf9rca/family-foqos/issues/507#issuecomment-5982327264): retain remaining unblocks, convert V1 reset weeks to days, with no refill/default fallback. The repair is a separate small PR before the next RC; never patch it into fixtures. The harness may expose the current failure, but a passing RC campaign must use a head containing that repair.
- Device-only proof remains on the single iOS 27 RC TestFlight checklist: App Store signing/container handoff, real Screen Time authorization/shields, NFC/camera/system scanner delivery, background timer/schedule/break delivery, and real iCloud/family sharing.

## Persona matrix

Fourteen personas, each in an isolated V1 store, produce 28 required persona/runtime verdicts. Defaults: Individual, completed onboarding, sync off, synthetic selections, unlocked profiles, a control profile, no geofence, 30-minute breaks when enabled, and an active session started two minutes before setup. Timer profiles save 37 minutes. Use V1’s actual strategy/tag/snapshot shapes, not V2 encoders. Add a completed session so history is visible; derive times from one setup `now`, without changing the simulator’s clock; the schedule window straddles `now` and remains open through the journey.

| Persona | V1 state at update | Actions after update and expected result |
|---|---|---|
| Manual focus | Manual session running | Open, check profile/history, Stop, restart and Stop. Existing session survives first launch; subsequent starts use converted Tap conditions. |
| NFC focus | Plain NFC session running with its scanned legacy identity | Stop opens NFC flow; wrong synthetic scan leaves it running, matching scan ends it. Start by scan, then matching scan stops the converted Same session. No invented Tap start. |
| QR focus | Plain QR session running with its scanned legacy identity | Same journey through the QR UI and scanner callback; wrong code cannot stop it. No invented Tap start. |
| NFC timer | NFC + Timer session running | End through its NFC flow, reopen settings, restart through the converted start UI. Saved 37-minute countdown is present and decreases; an allowed NFC scan stops it early. |
| QR timer | QR + Timer session running | Equivalent QR journey; saved countdown decreases and an allowed QR scan stops it early. |
| Shortcut timer | Hidden Shortcut Timer session running, valid saved duration | End using the retained legacy Stop flow; restart from the converted UI and inspect a decreasing saved-duration countdown. End the new timer-only session through Emergency Unblock; assert the allowance decreases, rather than inventing Tap stop. |
| Manual start / NFC stop | NFC + Manual running, with a Specific physical-unlock key | Stop opens scanner; wrong scan refuses, correct scan ends. Restart from UI, then repeat the required Specific stop. Settings retain the physical-stop requirement. |
| Manual start / QR stop | QR + Manual running, with a Specific physical-unlock key | Equivalent Specific QR journey; a wrong code never ends either old or new session. |
| Scheduled focus | Manual profile whose enabled V1 schedule is mid-window; schedule-origin session already running | Open without a duplicate session; inspect schedule, stop explicitly, background/return without restarting that occurrence, inspect separate converted start/stop schedules and restart/stop manually. OS schedule delivery is device-only. |
| Taking a break | Manual session with a still-open 30-minute V1 break | Open showing the same break/session, background/return, end break via its UI, then stop and restart focus. Preserve used break state; no fresh break allowance or duplicate session appears. |
| Emergency user | Manual running; two of three emergency unblocks used, reset date recent, two-week reset period | Inspect exactly one remaining unblock and a 14-day reset period; use the last unblock through UI, inspect zero after relaunch, then start/stop normally. No refill or default reset period on update. |
| Parent | Parent mode; locked Manual profile, running session, synthetic family lock-code response | Parent mode and locked profile remain; edit/save and start/stop through UI without a Child verification gate. Real family transport is substituted and reported. |
| Child | Child mode; locked Manual profile running, unlocked control profile, synthetic received lock-code response | Stop/restart/stop before entering any code: normal use needs no edit unlock. Locked edit/delete prompts verification; cancel/wrong code changes nothing, correct code permits editing. Creating/duplicating produces unlocked items. Mode and locked flag survive relaunch. |
| Established library | 24 uniquely named fixture profiles across the eight strategies, completed history, no active session; one never-started Manual, one missing-duration Shortcut Timer, and a saved synthetic location referenced by another profile | Scroll/select/edit/reopen first and last profiles; counts/history/settings remain. Inspect the saved location’s name/radius/coordinates and profile reference without starting that geofenced profile; this needs no GPS substitute. Start/stop the never-started profile. Invalid timer start shows the approved edit-required text and creates no session; repair timer through editor, save/reopen, start/count down, end through Emergency Unblock. |

Every journey captures V1 immediately before update, V2 first launch, the meaningful action/refusal, and final relaunch. Check visible profile settings (reminders, break duration, domain settings and locked state where applicable), not only Home. Background via `XCUIDevice.shared.press(.home)` then activate; separately terminate/relaunch without seed arguments. For active personas, the report compares the original session ID/start/break fields and proves conversion waits until that session ends; afterward the same profile is converted. Do not alter clock/state to keep a break alive: if setup-to-first-launch exceeds its 30-minute window, record it as unrun and retry a fresh seed. Capture and assert the exact approved text: “Please edit this profile before starting. Its start and stop settings need updating.”

## Review focus

- Xcode accidentally installs V2 before the V1 setup, or removes the store while switching builds: prove installed build and persistent sentinel at every phase.
- A second launch silently reseeds or migrates an active session: use one-shot V1 setup only, and unchanged identity/deferred-conversion checks.
- Timer-only conversion looks active but has no countdown: require UI decrease and accepted deadline evidence, without claiming OS expiry.
- Parent/Child transport substitutions bypass the edit lock itself: substitute responses only; verify wrong/cancel/correct flows and relaunch.
- Missing/stale reports or unexecuted UI tests look green: require fresh phase evidence, executed test identifiers, screenshots, and matching wrapper exit status.
