Build2 implements the [#572 design](../specs/2026-11-18-572-protected-launch-design.md) inline in its own worktree, using the executing-plans workflow. Start from the reviewer-approved plan head. Keep the spec and plan in the fix PR.

## Files and sequencing

Own `Foqos/FoqosApp.swift` (including AppDelegate and SceneDelegate), `Foqos/Utils/AppModelStore.swift`, `Foqos/Utils/TimersUtil.swift`, and the five model consumers in `Foqos/Intents/` (BlockedProfileEntity, StartProfileIntent, StopProfileIntent, CheckProfileStatusIntent, CheckSessionActiveIntent). Own `FoqosTests/StartupRecoveryOrderingTests.swift`, new `FoqosTests/ProtectedStoreLaunchTests.swift`, and new `FoqosUITests/ProtectedStoreLaunchUITests.swift` if needed. Use synchronized source groups. Keep the store owner in AppModelStore.swift. Build1 owns StrategyManager, SharedData and session tests. Neither stream edits the other’s files. For the one shared file, `FamilyFoqos.xcodeproj/project.pbxproj`, request the orchestrator’s version slot when ready. First finisher bumps both settings and merges; second merges current main with a signed merge, then bumps from that base. Final review and checks cover those exact heads.

## Implementation and checks

- [ ] **1. Make store opening retryable.** Add hosted tests for a main-actor owner with injected availability/probe, snapshot and throwing container factory. Table-test unavailable → waiting (zero opens and captures), unlock → one capture then one open, duplicate unlock/active/intent → identical container. Test ordinary cold relock with a readable existing store, a missing store while locked, a real factory error while accessible, and retry on the same store. Reuse StartupRecoveryLocalState.readStore for the existing-file read-only probe (tableMissing or profileCount proves a readable store; readFailed is inconclusive). Count calls and use a single fixed instant if testing successive launch events. Red first, then implement the state transitions from the spec using UIKit notifications and a foreground retry. Preserve the original snapshot on retry and surface a genuine store failure distinctly.
- [ ] **2. Gate the composition root.** Replace the global fatal initializer with the owner. Register it before first evaluation by a scene or an intent. Move the defaults-backed @StateObject properties and their factories behind the ready branch. A hosted construction-counter test drives launch, held push/BG entry, intent and scene evaluation while unavailable: zero settings readers, singleton constructions, device-ID reads or writes. After unlock assert the original Child mode, sync enablement, device ID and remote-session cache survive. Arrange the existing ready-only root and its model modifier to receive the successful container. Keep the startup snapshot ahead of all side effects that can classify or seed local state. Check init, demo seed, all scene modifiers and coordinator registration. Until ready, queue delivered share metadata/URLs in memory for normal arbitration after unlock, with the existing deduplication. Keep BG registration and notification delegate setup at launch. A BG task before readiness completes once without consuming stored tasks. Preserve the push router’s held completion. Verify the post-unlock handoff when unlock occurs before a scene mounts. Maintain the recovery ordering tests with behavioural assertions.
- [ ] **3. Exercise non-scene callers.** Register a resolvable provider at app init so the five App Intent consumers can request the ready store through a throwing API. Resolve the provider/store into a local value before evaluating any StrategyManager.shared or AppModeManager.shared receiver. Audit metadata access as well: before protected defaults are readable, ShortcutsSettings.authenticationPolicy uses its fail-closed authentication requirement without reading defaults, and honors the stored choice on ordinary relock with accessible data. Preserve explicit test-container injection in BlockedProfilesQuery. Test locked query/start/status failure, then success after unlock without relaunch or double initialization. Verify ready-background intents still work on an ordinary relock. Check cold and warm share/URL delivery and background processing during the wait. Do not block a callback indefinitely waiting for unlock.
- [ ] **4. Run acceptance.** Use a test-only injected protection signal on the simulator. Seed a real temporary store and profile, start a fresh process with unavailable data, verify the waiting UI and dormant normal root, deliver unlock, then verify the same profile and normal root appear once. Repeat unlock/foreground, and cover an accessible-store error with explicit retry. Preserve existing normal, fresh-install recovery, demo and V1 migration tests. Launch with the injection disabled for the normal path. Keep test injection out of release builds. A simulator reboot alone does not establish first-unlock file protection. For the existing RC device pass, record a passcode-enabled reboot with an active Live Activity, any observed pre-unlock launch, survival through unlock and profile preservation. If iOS does not deliver the wake, record that fact.
