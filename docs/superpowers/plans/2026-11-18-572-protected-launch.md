## Implementation and checks

- [ ] **1. Make store opening retryable.** Add hosted tests for a main-actor owner with injected availability/probe, snapshot and throwing container factory. Table-test unavailable → waiting (zero opens and captures), unlock → one capture then one open, duplicate unlock/active/intent → identical container. Test ordinary cold relock with a readable existing store, a missing store while locked, a real factory error while accessible, retry on the same store, and a relock between probe and open. Count calls and use a single fixed instant if testing successive launch events. Red first, then implement the state transitions from the spec using UIKit notifications and a foreground retry. Preserve the original snapshot on retry and surface a genuine store failure distinctly.
- [ ] **2. Gate the composition root.** Replace the global fatal initializer with the owner. Register it before first evaluation by a scene or an intent. Arrange the existing ready-only root and its model modifier to receive the successful container. Keep the startup snapshot ahead of all side effects that can classify or seed local state. Check init, demo seed, all scene modifiers and coordinator registration. Until ready, queue delivered share metadata/URLs in memory for normal arbitration after unlock, with the existing deduplication. Keep BG registration and notification delegate setup at launch. A BG task before readiness completes once without consuming stored tasks. Preserve the push router’s held completion. Verify the post-unlock handoff when unlock occurs before a scene mounts. Maintain the recovery ordering tests with behavioural assertions.
- [ ] **3. Exercise non-scene callers.** Register a resolvable provider at app init so the five App Intent consumers can request the ready store through a throwing API. Preserve explicit test-container injection in BlockedProfilesQuery. Test locked query/start/status failure, then success after unlock without relaunch or double initialization. Verify ready-background intents still work on an ordinary relock. Check cold and warm share/URL delivery and background processing during the wait. Do not block a callback indefinitely waiting for unlock.
- [ ] **4. Run acceptance.** Use a test-only injected protection signal on the simulator. Seed a real temporary store and profile, start a fresh process with unavailable data, verify the waiting UI and dormant normal root, deliver unlock, then verify the same profile and normal root appear once. Repeat unlock/foreground, and cover an accessible-store error with explicit retry. Preserve existing normal, fresh-install recovery, demo and V1 migration tests. Launch with the injection disabled for the normal path. Keep test injection out of release builds. A simulator reboot alone does not establish first-unlock file protection. For the existing RC device pass, record a passcode-enabled reboot with an active Live Activity, any observed pre-unlock launch, survival through unlock and profile preservation. If iOS does not deliver the wake, record that fact.
