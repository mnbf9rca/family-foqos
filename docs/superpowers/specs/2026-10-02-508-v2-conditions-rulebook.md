# V2 conditions rulebook (#508)

**Status:** revised contract awaiting final human approval of the rulebook; all user-facing copy below is approved. Independent technical review is reported separately. No implementation child of #507 starts before human approval.

**Intent:** a profile starts through any enabled start and ends through any applicable configured stop. Changing a start never silently changes a stop. V2 conditions replace V1 strategy behaviour as the runtime and test oracle.

**Sources:** [epic #507](https://github.com/mnbf9rca/family-foqos/issues/507), [rulebook #508](https://github.com/mnbf9rca/family-foqos/issues/508), all children (#509–#521, #493, #59), the [unaltered audit](../../audits/2026-10-02-v1-leakage-audit.md) and its [NFC-casing correction](../../audits/2026-10-02-v1-leakage-audit-corrections.md). Audit source is `0fa5f9d92caddde49ec3e8f9e3859a254bdb3d59`; this branch starts at `origin/main` `8e4ee25e977116c17508ca0af20bfc6636f905f6`, including #501's #322 plan. This revision applies the auditor's coverage check of `8ff43a5`; its three acceptance gaps and four stale ruling groups are addressed below.

## Binding rulings, verbatim from #507

- **R1:** V2 start and stop conditions are independent and combine freely. No pairing logic and no reuse of V1 strategy behaviour.
- **R2:** Every profile needs a stop condition, enforced in the editor and checked at every start (including synced, scheduled and link starts).
- **R3:** The Timer stop must start a real countdown on every kind of start; the duration is stored with the stop setting.
- **R4:** "Same tag" means the tag that started this session. It does not apply to sessions started any other way. If a profile can start any other way, it must also have a stop that does not rely on the same tag (editor save rule).
- **R5:** Remove the "Disable Background Stops" safeguard entirely. It is V1-era (commit 6707902) and redundant in V2; the profile's own stop options alone decide what can end a session. Scheduled stops the user configured must always fire.
- **R6:** If the timer cannot be registered, refuse to start and show an error; never run a session without its timer. Timer expiry may only end its own session.
- **R7:** Scheduled starts missed while the device was off are not caught up later.
- **R8:** The editor refuses start and stop configured for the same moment; at runtime, if both are due, the stop wins.
- **R9:** NFC and QR stop kinds (None, Any, Same, Specific) are a single choice per tag type and must be stored as a single value, not separate flags; normalise incoming synced data.
- **R10:** A tag is one concept, whether scanned in the app or opened in the background as a written-tag or QR link. Remove the separate link stop option. While profile A is active, scanning profile B's tag or QR: if A stops on "any" of that type, A ends and B starts; if A stops on "specific" or "same", the app asks for an in-app scan of the required tag first; if A has no stop of that type, A keeps running and B does not start. Link starts are unchanged: scanning a profile's link still starts that profile.
- **R11:** The audit report gets committed under docs/ and AGENTS.md gets a rule that V2 conditions are independent and V1 strategy behaviour must not be reused (done by the planner with the rulebook).

## Later binding decisions and release scope

- Same must work on the account's other devices: sync the session's initiating identity and origin. A pre-update mirror without identity cannot stop by Same on that device; missing identity never means Any. No recovery mechanism or special notice is added (former G6 is dropped).
- Timer duration is saved in the profile. Interactive adjustment is session-only, controlled by the approved profile option. Tag, link, Shortcut and scheduled starts use the saved duration. An old Shortcut sending Duration is refused with the approved message. Child may adjust when the option is enabled, even on a locked profile; editing the option remains protected by the existing lock (G2 settled).
- A V1 Timer missing a valid duration has no operational Timer stop until repaired on the next edit; no default is invented. Another valid applicable stop may permit a start; a timer-only profile cannot start (G3 settled).
- Late OS callbacks are best effort. Skip a late start if a stop occurrence has passed since that start occurrence; otherwise accept it once. No foreground catch-up or invented timeout (G4 settled).
- Keep V1 reading and conversion until the human sets a removal cutoff; add no telemetry and give V1 fields no authority over converted V2 behaviour (G5 settled policy; future cutoff undecided).
- New app-written NFC and generated QR links use `/profile/<id>/<nfc-or-qr>/<random>`, with a short random opaque key shared by in-app and background readers. Old app-written no-ID payloads retain in-app NFC UID/QR digest matching; old background tag links satisfy Any only of their verified NFC/QR type. Ordinary links satisfy no tag condition. The latest verified-type approval supersedes the earlier Any-either-type ruling; G7 identity preservation remains settled.
- In-app scans follow exactly the same R10 A-to-B flow as background taps. Preserve the signature and optional target; when A accepts B's tag, A ends and eligible B starts. During an explicit Start on P, check the scan against P's start and ignore its linked target (B9). Outside that operation, a linked tag targets B when no profile runs or a different A runs. B admits that tag if Link is on **or** B's NFC/QR start accepts it, in either route (B10). Other link commands require Link, start only while idle and never end an active profile. A required-key confirmation belongs to the pending B operation and never accidentally changes its target.
- Plain V1 NFCBlockingStrategy/QRCodeBlockingStrategy convert to Any NFC/QR start and Same NFC/QR stop, with no added Link or no-duration Shortcut entrance. Users may enable those later after adding a non-Same stop. The other six strategies keep every V1 entrance, including Link and no-duration Shortcuts. A converted profile violating V2 rules is retained, marked invalid and refused at every originating start with an edit-required message. No hidden fallback, lost entrance or invented stop.

**V2 has not shipped to the App Store.** Protect V1 user data, physical tags and behaviour while genuinely unmigrated; defer conversion of an active V1 profile until its session ends, as the existing migration boundary does. V1 already promised Same NFC/QR through its strategies. Keep that data for conversion; do not claim Same itself is V2-only.

Remove work protecting only previously installed V2/TestFlight states: active/inactive V2 Link-only grandfathering and bespoke repair, old V2 mirrored-identity hydration/notices, dedicated repair of V2-created duration-less flags, and wire shims only for unreleased V2 readers. The earlier Link-only grandfather ruling is superseded by this release scope. General malformed-data refusal, preservation of authoritative active blocking state, V1 durations/keys/schedules/reader compatibility and normal new-session identity sync remain. Retain narrowly version-gated V1 active-session behaviour; do not reinterpret or silently end those sessions during conversion.

## Conditions and owned data

Enabled starts are OR alternatives: Manual, NFC (Any or Specific), QR (Any or Specific), Shortcuts, Link and Schedule. Specific starts own nonempty key sets; Schedule start owns its recurrence. No start implies a stop. Preserve the requirement to select at least one start.

Enabled stop families are OR alternatives. Each tag type has one selected kind. Failure in one family does not disable another. Stop-owned data survives save/reopen, duplication, private-account sync and app-group snapshots.

| Stop | Required data and meaning |
| --- | --- |
| Manual | Enabled flag. Explicit tap or authorized Shortcut stop, independent of start. Existing Shortcut/device-unlock gates remain. |
| Timer | Enabled flag, saved duration and interactive-adjustment option. An operational Timer is established on every originating start and publishes its accepted deadline. |
| NFC None / QR None | No stop of that type. |
| NFC Any / QR Any | Any successfully read key of that type, independent of start. An old unidentified link on a verified tag route can satisfy Any only of that route’s type. |
| NFC Same / QR Same | This session's initiating typed key. Ordinary non-tag starts have no Same origin; a permitted unidentified legacy-tag session has the explicit Any-session meaning below. |
| NFC Specific / QR Specific | Nonempty configured key set; match a key in it regardless of start. Missing keys invalidate configuration, with no downgrade to Any. |
| Schedule | Enabled flag and active recurrence: nonempty valid weekdays, hour 0–23, minute 0–59, existing calendar/time-zone conventions. Own day/time check. |

There is no Link stop option or V2 runtime authority from its old Boolean. Link start remains a configured entrance; a targeted tag may alternatively qualify through its NFC/QR start under B10. Only a verified tag event is subject to the active profile's tag stops under R10; other link opens cannot end it.

### Tag identity and delivery

For newly app-written NFC and generated QR codes, **type plus random opaque identifier** is the matching key in both paths. Generate a distinct short random key per logical tag/code and retain it when reusing that code. Read it from the recognized `/profile/<id>/<nfc-or-qr>/<random>` link; do not derive it from the profile UUID. Validate scheme/host, exact path fields, known type and usable identifier. A malformed identified link fails; it is never treated as a permissive old link.

For a successful in-app read of a legacy app-written no-ID profile payload, preserve NFC chip UID or normalized/raw QR content digest identity. Read existing unnamespaced physical keys and session origins in their legacy UID/digest namespace. Only typed links with an ID use the opaque namespace. This preserves existing Specific keys and the scan used to confirm them. An old **background** UUID-only link cannot prove Specific: its verified-route Any meaning is distinct from an actual in-app legacy scan with a UID/digest.

Non-app-written in-app NFC retains UID identity; non-profile QR retains normalized SHA-256 and raw-digest compatibility. NFC UID text is **uppercase hexadecimal, exactly as `NFCScannerUtil.hexEncodedString` produces** (`%02hhX`). Keep opaque keys, UIDs and content digests in distinct comparison namespaces. SavedTag's hashed record name is not its NFC matching key. Identical QR payloads are the same key; static keys can be copied, so matching does not prove physical authenticity.

Both in-app scanners retain the canonical signature **and optional target profile** from recognized NDEF URI/scanned profile text, through the same validated boundary parser as background opens. Explicit Start on P uses only the signature to check P's selected NFC/QR start and ignores the payload's target; a confirmation uses its pending target rather than replacing it. A UID/non-profile QR with no target can stop A but cannot invent B. New and old recognized profile payloads can carry B. The current code retains only `webpageURL` and profile UUID; #521 must preserve the activity's scanner metadata at this boundary. Keep the human-selected path suffix; verify older V1 readers and associated-domain matching (current NavigationManager resolves its first two path segments).

A reader/NDEF error fails the scan with retry; never fall back to UID or enroll under the wrong identity after a transient failure. A successful read finding no NDEF or non-profile content uses UID. A successful old no-ID profile read uses the approved legacy identity.

**Delivery classification:** an in-app NFC/QR reader identifies its scan type directly. At `onContinueUserActivity`, identify background NFC only when `ndefMessagePayload` contains a recognized URI record (well-known `U` or absolute URI) whose decoded URL matches `webpageURL`. Non-NFC activities contain an empty-format sentinel record, so a nonzero record count is insufficient. Identify a system QR scan only when `detectedBarcodeDescriptor` is a non-nil QR descriptor. Otherwise it is another link open (including Safari, Messages, Notes, Shortcut Open URL or a third-party scanner app), can start only through Link while no profile runs, and never satisfies a tag stop or ends/switches an active profile; do not infer a scan from its URL suffix, `referrerURL` or a user-selected type. The parser supplies the logical key/type. A known scan route whose type disagrees with a typed payload fails with C22, before admission or effects. Only verified tag events capture a Same identity; an ordinary link command has no Same origin even if its URL contains a typed key. An untyped legacy link on a verified NFC route satisfies NFC only; on a verified QR route it satisfies QR only. This applies to start admission, stop matching and the unidentified-session Same exception. Ordinary links satisfy neither type. These metadata APIs predate the 18.6 deployment target: [Apple NFC delivery](https://developer.apple.com/documentation/corenfc/adding-support-for-background-tag-reading), [Apple barcode descriptor](https://developer.apple.com/documentation/foundation/nsuseractivity/detectedbarcodedescriptor).

Camera and Control Center Code Scanner handoff must be verified on devices before #521 is accepted. If a supported system scanner does not populate the descriptor, classify its unverified open as another link at runtime, report the failure and stop/ask through orchestrator before shipping; never silently classify its URL payload as a scan or relax Link admission. Actual metadata delivery is a device-evidence requirement, not a claim of completed verification. Shortcuts App Intent remains governed by Shortcuts, independently of Shortcut Open URL.

**N8, approved:** before writing an NFC tag or generating a QR code, check whether Link or the matching NFC/QR start admits the resulting type/key. If neither does, refuse through the existing error surface with C24; no new UI and no silently enabled start or Specific key.

### Timer configuration and adjustment

Duration is an integer in `DeviceActivityLimits.minimumIntervalMinutes...maximumTimerMinutes` (currently 15...1439 minutes). New saves require a valid value when Timer is enabled. Reject malformed, zero, negative and out-of-range values; never clamp or use the old decoder's silent 15-minute default. Transfer only genuinely decoded valid V1 durations. A missing/invalid V1 duration leaves Timer selected but **inert**, needs repair at next edit, and is not counted as an operational stop. Another valid applicable stop can permit a new start; absent one, mark invalid and refuse Start. An active authoritative session is not discarded by this check.

The approved option is **Allow changing timer before start**. Off: all starts use the saved duration. On: interactive manual start offers adjustment before registration; cancellation starts nothing, and the accepted adjustment changes only that session. Locked Child use requires no additional unlock. Saving duration/option still uses the profile edit lock. NFC/QR, Link (even foreground delivery), Shortcut and scheduled starts always use the saved value. An old Shortcut passing Duration is refused with the approved table message; it cannot bypass validation or invoke a V1 timer strategy.

## Every start × stop combination

Cells assume a **valid admitted configuration**, enabled start and valid stop-owned data. **Yes** is independent of origin, **Own** is an established session countdown, **Same** matches its initiating key, and **—** is inapplicable. A row with — needs another applicable stop. NFC/QR None is always inapplicable. Any/Specific scan starts use their type's row; Timer-inert V1 repair is the explicit exception to an operational Timer column.

| Origin | Manual | Timer | NFC Any | NFC Specific | NFC Same | QR Any | QR Specific | QR Same | Schedule |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Manual | Yes | Own | Yes | Yes | — | Yes | Yes | — | Yes |
| Identified NFC scan or verified typed NFC event | Yes | Own | Yes | Yes | Same | Yes | Yes | — | Yes |
| Identified QR scan or verified typed QR event | Yes | Own | Yes | Yes | — | Yes | Yes | Same | Yes |
| Shortcut without Duration | Yes | Own | Yes | Yes | — | Yes | Yes | — | Yes |
| Unidentified legacy NFC event on verified NFC route | Yes | Own | Yes | Yes | Any* | Yes | Yes | — | Yes |
| Unidentified legacy QR event on verified QR route | Yes | Own | Yes | Yes | — | Yes | Yes | Any* | Yes |
| Other link command | Yes | Own | Yes | Yes | — | Yes | Yes | — | Yes |
| Scheduled monitor callback | Yes | Own | Yes | Yes | — | Yes | Yes | — | Yes |

**Any*** describes only the stop meaning for a **permitted** session started through a verified tag route carrying an unidentified legacy background link. Only the configured Same kind matching the verified initiating route behaves as Any of that type for that session; the opposite Same kind remains inapplicable. Record the verified route and unidentified origin explicitly, preserve them on new mirrors, and clear them on replacement/completion. It never weakens Specific or ordinary non-tag origins. It is **not an invalid-configuration exception**: an invalid converted profile refuses every new start, including an old link. A valid plain converted NFC/QR profile can admit an old linked-tag event of its own verified type through its Any NFC/QR start with Link off under B10; its unidentified background origin then uses this per-session stop meaning. A valid legacy in-app UID/digest start has a captured identity and uses Same matching, rather than the unidentified-link exception.

A same-account mirror adopts authoritative origin/key and accepted deadline without a second timer. Replace identity on a new session and clear it at completion. A pre-update mirror without start identity simply cannot stop through Same on that device; never infer Any from missing data, hydrate it or add a special notice. Preserve authoritative blocking state separately from admission checks.

## Save, duplication, sync and every-start checks (#493, #511–#513, #520)

Offer every stop choice, including Same, regardless of starts. Changing starts never hides, clears or rewrites stops/data. Refuse Save with the table's descriptive error rather than deleting selections.

Save/clone require valid starts, nonempty well-formed stops and R4 coverage. If Same NFC is selected with an ordinary non-NFC start (Manual, Shortcut, Schedule or identified QR), require a non-Same stop; QR is symmetric. Two Same kinds alone do not satisfy the additional non-Same requirement for NFC+QR starts. The single Link flag admits both typed NFC and typed QR, so Link plus any Same also needs a non-Same stop. A selected Same with no corresponding origin can remain alongside a valid non-Same stop, with its explanation.

Validate the whole configuration and actual-origin applicability at **every originating boundary** before restrictions, insertion/publication, ending an existing session or takeover effects: manual/Home, NFC/QR Any/Specific scans, no-duration Shortcut, typed NFC/QR URLs, legacy URL, monitor schedule and any direct/shared creator. A legacy URL does not bypass invalid-profile admission. For a targeted tag/code event, admit B when Link is enabled **or** its matching NFC/QR start accepts the presented signature; typed events match type/key, and unidentified legacy background events qualify as Any only of the verified route’s type, never Specific. Both delivery routes use this OR rule, so a valid plain converted NFC/QR profile starts from its written tag with Link off. An actual legacy in-app scan retains its UID/digest for Specific matching. Non-scan link commands can use the Link entrance only while idle and cannot end a running profile; explicit Start-on-P scans use P's selected NFC/QR entrance and ignore any linked B. An inert V1 Timer follows the approved repair rule; an operational Timer must really register. Specific stop keys need not equal start keys. Remove `hasUsableStop` and its credential-pair/background-veto predicate.

Retain invalid incoming/converted profiles, mark them invalid through the common validation result and show the friendly edit-required message. Do not invent stops, erase entrances, count emergency unblock as a configured stop or discard restored blocking state. Existing selection, Screen Time, mode, edit-lock and applicable geofence checks remain. Timer/Schedule expiry is never vetoed by geofence or a background setting.

For #520, normalize any incoming flag triplet at its decoding/conversion boundary once: **Specific > Same > Any > None**, independently per type. Missing Specific keys remain invalid, with no fall-through to Any. Store canonical single values; recognized canonical values beat old flags, unknown/malformed values invalidate rather than fallback. Normalize snapshots consistently before validation. No OR interpretation, start-dependent mutation, new strategy hierarchy or shims solely for unreleased V2 clients. Genuine V1 conversion/reader compatibility remains bounded to that schema.

## V1 conversion contract and matrix

Conversion applies the latest explicit plain NFC/QR exception and otherwise preserves all evidenced V1 entrances, then runs the **same final R2/R4/data validator**. Do not drop additional entrances to make its output valid. The table shows known strategy stops before physical-unlock/schedule modifiers; unlisted starts are off. Link and no-duration Shortcuts are preserved for the six non-plain strategies; they remain off for the two plain Same strategies under the final ruling. NFC/QR strategy buttons keep their scan action, not an invented immediate Manual start.

| V1 strategy | Required V2 starts | Converted stops before modifiers | Result with valid owned data |
| --- | --- | --- | --- |
| ManualBlockingStrategy | Manual, Shortcuts, Link | Manual | Valid |
| NFCBlockingStrategy | Any NFC | Same NFC | Valid; Link and Shortcuts remain off |
| NFCManualBlockingStrategy | Manual, Shortcuts, Link | Any NFC | Valid |
| NFCTimerBlockingStrategy | Manual, Shortcuts, Link | Any NFC, Timer | Valid; missing duration makes Timer inert |
| QRCodeBlockingStrategy | Any QR | Same QR | Valid; Link and Shortcuts remain off |
| QRManualBlockingStrategy | Manual, Shortcuts, Link | Any QR | Valid |
| QRTimerBlockingStrategy | Manual, Shortcuts, Link | Any QR, Timer | Valid; missing duration makes Timer inert |
| ShortcutTimerBlockingStrategy | Manual, Shortcuts, Link | Timer | Valid only with operational Timer or another valid modifier stop |

Physical-unlock conversion replaces Any/Same for that modality with Specific and its legacy key. An opposite-modality physical key supplies an additional independent Specific stop; valid keys can satisfy R4. Preserve the existing NFC-first choice if both legacy physical fields exist; do not invent a new precedence. Active valid V1 schedules convert to separate start/stop recurrences and enable both; disabled schedules enable neither. Validate recurrence/R8 constraints, keys and durations after all modifiers. Do not silently normalize invalid product choices into permissive alternatives.

Bare NFCBlockingStrategy and QRCodeBlockingStrategy stay valid with their clean scan-start/Same-stop mapping. Enabling Link or Shortcuts later invokes the editor's non-Same-stop requirement, with no automatic stop addition. An active V1 schedule adds both schedule starts/stops, so a valid stop recurrence supplies non-Same coverage. Any converted profile that is invalid after the approved mapping and all modifiers is retained, marked invalid and refused at **every** originating start with the edit-required copy; save/clone refuse until corrected. Missing-duration ShortcutTimer is invalid without another operational modifier stop; NFC/QR timer families keep Any. An unknown **non-nil** V1 strategy ID used the V1 factory’s NFC fallback: convert it as plain NFC (Any NFC start, Same NFC stop, no added Link/Shortcuts). A **nil** ID did nothing on the V1 Start button: preserve no button start, retain the data, mark invalid and use C18 until edited; do not invent Manual start/stop. Keep the evidenced Link/no-duration Shortcut entrances of that nil record as data, without admitting an invalid profile. Neither case uses current TriggerMigration’s invented Manual/Manual default. Protect active V1 sessions and defer conversion until they end.

## Countdown establishment, expiry and cleanup (#509–#510)

For an operational Timer, prepare session identity and validated saved/interactive duration, register once and obtain the accepted deadline **before exposing a new active session or restrictions**. App and monitor paths share this contract across their processes. Reuse the existing registrar/activity machinery after removing V1 behaviour; do not instantiate V1 timer strategies for V2 starts. An inert duration-less V1 Timer registers nothing and must pass admission through another valid stop.

Registration failure refuses start with the proposed timer error, even when another stop is selected; leave an existing session untouched. Subsequent persistence/publication failure cancels the provisional countdown and reports failure. No stray callback creates a session or applies restrictions. Recheck ownership before takeover; a race cancels the candidate timer rather than ending the winner.

Expiry checks exact session identity and accepted deadline, using expected-session guards. Missing/replaced/same-profile-later sessions and early callbacks are no-ops; duplicate completion is idempotent. Authorized early stop, deletion or takeover cancels only the departing timer. Publish/clear timing and origin consistently locally, in shared snapshots and private sync. A mirror adopts the authoritative countdown and matching completion flow, never another registration. OS timing is best effort; device evidence is required for actual delivery.

## Independent schedule recurrences (#515–#517)

Start and stop each own recurrence and OS registration. Reuse the stop-only activity; its registration/removal cannot depend on successful start registration. A V2 start activity's artificial end does nothing. OS minimum intervals constrain internal windows, not the gap between product events.

Monday 09:00 start / Friday 17:00 stop never stops on Monday at 17:00. Equal clocks on disjoint weekdays and distinct events less than 15 minutes apart are valid if each OS registration is valid. Refuse Save only for enabled recurrences sharing a weekday and equal hour/minute. Runtime stop wins regardless of callback order; a start cannot resurrect an already-stopped occurrence. Keep existing stopped-occurrence suppression, without catch-up.

Remove foreground/app-launch/refresh creation for historical starts; refresh can register future activities and reconcile existing authoritative sessions/reminders. On an actual late OS callback, use a pure recurrence query: skip if a stop occurrence lies from that start occurrence through delivery time, including equal-moment precedence; otherwise accept once. No persisted stop-callback history or arbitrary grace period. Scheduled takeover keeps outgoing Manual-stop and permitting-geofence requirements, with the existing skipped-start notification otherwise; remove only the background veto. Incoming validation/countdown establishment precedes takeover effects.

Stop callbacks check their own recurrence and matching profile/session regardless of how it started, never a V1 combined schedule or artificial start end. R5 guarantees accepting a configured due stop, not exact iOS execution. After migration, V2 fields alone control registration/callback/cleanup/display. Turning a condition off removes obsolete activities; retained legacy columns cannot restart it. Genuine unmigrated V1 active sessions keep version-gated handling until their existing lifecycle ends.

## One tag concept and switching (#521)

Remove separate Link stop authority from V2. **Both in-app and background delivery** produce signature plus optional B target. An explicit Start on P checks the signature against P's selected start and ignores B, including when nothing is running. Outside an explicit start, a targeted tag starts B when no profile runs; when a different A runs, apply the table below. B is eligible if its Link start is on **or** its NFC/QR start accepts the event, identically in both routes. New typed links use type/key; old unidentified links count as Any only of the verified tag route’s type. Other link commands require Link, start only while idle and never end an active profile. A targetless scan does not invent B. Delivery route does not change the saved Timer duration.

| A's kind for the event type | Result when B is targeted |
| --- | --- |
| Any | A ends and valid B starts; an old unidentified background link may satisfy Any only of its verified tag route’s type. |
| Specific or Same | Accept a genuinely matching presented key in either path. If absent/wrong, ask for A's required in-app key first; cancellation, read failure or wrong proof leaves A running and B pending/unstarted. |
| None | A keeps running and B does not start, even if Manual or the other tag type is enabled. |

Apply delivery classification before any stop or switch match: an ordinary link command cannot satisfy NFC/QR conditions and leaves A running, even if B enables Link. For verified tag events, validate B, prepare its Timer if operational and recheck exact A ownership before ending A. B failure leaves A untouched and cancels only candidate registration. Keep B fixed while confirming A's required key; that proof cannot replace B's target or initiating identity. Clean up A's timer without cancelling B's. Existing applicable mode/geofence authorization remains; no background veto or V1 force-start bypass. Verified tag events carrying old unidentified links satisfy Any only of the verified route’s type and cannot prove Specific; other link commands never do. Same on an otherwise admitted session started through one has the explicit per-session meaning; malformed IDs and missing ordinary mirror identity do not.

## Background stops and presentation (#514, #518–#519)

Remove Disable Background Stops setting/UI/authority and contrary tests from V2. Old values are ignored on its schedule, tag/link and Shortcut stop paths; decode-only V1 columns may remain. Keep genuinely unmigrated V1 active behaviour at its version boundary. Requests require matching session and configured stop: Shortcut uses Manual, verified tag events use the common matcher, Schedule its recurrence, Timer its owned expiry. Ordinary link commands never authorize a stop.

Cards show separate V2 start/stop summaries with existing labels/icons; V1 labels only for genuinely unmigrated profiles. Distinct weekdays/times stay intelligible. Timer+Schedule is valid; warn only on actual invalid data/failure, not combination. Configured duration describes settings; active countdown uses accepted deadline, including adjustment/mirror timing. Card/widget/Shortcut status agree. A valid established timer-only session need not offer immediate Manual stop.
