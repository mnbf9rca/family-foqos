# V2 conditions rulebook (#508)

**Status:** proposed contract for human approval; independent reviewer verdict is reported separately. No implementation child of #507 starts before human approval. Unresolved gates below are not decisions.

**Intent:** a profile starts through any enabled start and ends through any applicable configured stop. Changing a start never silently changes a stop. This document replaces V1 behaviour used as a V2 product oracle.

**Sources:** [epic #507](https://github.com/mnbf9rca/family-foqos/issues/507), [rulebook #508](https://github.com/mnbf9rca/family-foqos/issues/508), all epic children (#509–#521, #493, #59), and the [unaltered auditor report](../../audits/2026-10-02-v1-leakage-audit.md) with its [dated NFC-casing correction](../../audits/2026-10-02-v1-leakage-audit-corrections.md). The audit's code/line evidence is pinned to `0fa5f9d92caddde49ec3e8f9e3859a254bdb3d59`; this branch starts at `origin/main` `8e4ee25e977116c17508ca0af20bfc6636f905f6`, including #501's #322 plan. Later human rulings override audit recommendations, especially its Same-to-Any fallback and retained background veto.

## Binding rulings, verbatim from #507

- **R1:** V2 start and stop conditions are independent and combine freely. No pairing logic and no reuse of V1 strategy behaviour.
- **R2:** Every profile needs a stop condition, enforced in the editor and checked at every start (including synced, scheduled and link starts).
- **R3:** The Timer stop must start a real countdown on every kind of start; the duration is stored with the stop setting.
- **R4:** "Same tag" means the tag that started this session. It does not apply to sessions started any other way. If a profile can start any other way, it must also have a stop that does not rely on the same tag (editor save rule).
- **R5:** Remove the "Disable Background Stops" safeguard entirely. It is V1-era (commit 6707902) and redundant in V2; the profile's own stop options alone decide what can end a session. Scheduled stops the user configured must always fire.
- **R6:** If the timer cannot be registered, refuse to start and show an error; never run a session without its timer. Timer expiry may only end its own session.
- **R7:** Scheduled starts missed while the device was off are not caught up later.
- **R8:** The editor refuses start and stop configured for the same moment; at runtime, if both are due, the stop wins.
- **R9:** NFC and QR stop kinds (None, Any, Same, Specific) are a single choice per tag type and must be stored as a single value, not separate flags; normalise incoming synced data.
- **R10:** A tag is one concept, whether scanned in the app or opened in the background as a written-tag or QR link. Remove the separate link stop option. While profile A is active, scanning profile B's tag or QR: if A stops on "any" of that type, A ends and B starts; if A stops on "specific" or "same", the app asks for an in-app scan of the required tag first; if A has no stop of that type, A keeps running and B does not start. Link starts are unchanged: scanning a profile's link still starts that profile.
- **R11:** The audit report gets committed under docs/ and AGENTS.md gets a rule that V2 conditions are independent and V1 strategy behaviour must not be reused (done by the planner with the rulebook).

Additional human rulings relayed by orchestrator on 2026-10-02:

- Same tag on a mirrored session: **yes, it must work on the account's other devices**; mirror the session's start tag along with the profile.
- Late OS callbacks: **best effort**. No invented lateness timeout or exact-delivery promise.
- Timer duration is set in the profile. A profile option allows adjusting it before an interactive start. Background, tag and scheduled starts always use the saved value.
- Newly written NFC tags and generated QR codes carry type and a short random opaque identifier in `/profile/<id>/<nfc-or-qr>/<random>`. That identifier is their matching identity for both in-app scans (reading the link) and background opens. Raw chip UID remains only for non-app-written NFC tags scanned in-app.
- Existing links without an identifier satisfy Any of either type. A Same-tag profile started from such a link behaves as Any of its configured type for that session. This is an explicit legacy-session exception; do not generalize it to manual/scheduled/Shortcut starts.
- A link is a direct profile command; an in-app scan presents an opaque signature. In-app readers parse written-link identity but do not turn an in-app signature scan into a command starting another profile.
- A Link-only session already active at upgrade, locally or mirrored, retains its Link exit until that session finishes; afterwards the profile must follow the new stop rules.
- That option is part of the agreed profile definition. When enabled, a Child may adjust duration at start, including for a locked profile. The existing lock protects editing the option itself; add no extra Child-mode restriction. Exact copy, adjustment persistence and missing-duration repair remain human gates.

## Conditions and owned data

Enabled starts are OR alternatives: Manual, NFC (Any or Specific), QR (Any or Specific), Shortcuts, profile deep link, and Schedule. Specific starts own their respective nonempty key sets; Schedule start owns its recurrence. No start carries an implied stop. Preserve the existing requirement to select at least one start.

Enabled stop families are OR alternatives. Within each tag type select exactly one kind. A failed tag match does not disable another stop family. Stop-owned data must survive editor save, duplication, private-account sync and app-group snapshots.

| Stop | Required data and meaning |
| --- | --- |
| Manual | Enabled flag. Explicit tap/authorized Shortcut stop; neither requires a matching start. Existing Shortcut/device-unlock gates still apply. |
| Timer | Enabled flag plus valid saved duration and the profile option controlling interactive adjustment. Every originating start registers a countdown and records its accepted deadline. |
| NFC None / QR None | No stop of that type. |
| NFC Any / QR Any | Accept any successfully read tag/code of that type; no start-key restriction. |
| NFC Same / QR Same | Match the typed comparison key captured by this session’s identified scan/link origin. An unidentified legacy-link origin uses the explicitly approved per-session Any exception below; ordinary non-tag starts do not. |
| NFC Specific / QR Specific | Nonempty configured stop-key set, independent of start keys. Match a key in that set, regardless of start modality. Missing/unusable keys invalidate configuration; do not downgrade to Any. |
| Schedule | Enabled flag plus an active recurrence: nonempty valid weekday set, hour 0–23, minute 0–59, using the existing calendar/time-zone conventions. Stop checks its own recurrence. |

For newly app-written NFC tags and generated QR codes, **type plus the random opaque identifier** is the matching identity, shared by both delivery paths. Read it from the recognized link, shaped `/profile/<id>/<nfc-or-qr>/<random>`. Generate a short random identifier per logical tag/code, retain it when displaying/reusing that code, and keep distinct keys distinct; do not derive it from the profile UUID. Validate scheme/host, exact path fields, known type and usable identifier at the boundary; malformed identified links fail rather than degrading into a permissive legacy event. Do not trust arbitrary text that happens to contain a profile path.

For non-app-written NFC scanned in-app, the fallback identity is raw chip UID in **uppercase hexadecimal, exactly as `NFCScannerUtil.hexEncodedString` produces** (`%02hhX`). For non-profile QR content, retain existing normalized SHA-256 and raw-content hash compatibility. **Old app-written no-ID NFC/profile-QR in-app identities are G7, not implicitly removed or silently migrated**: proposed UID/digest compatibility and unnamespaced-key interpretation require that human decision before #521 proceeds. Keep linked opaque IDs, raw NFC UIDs and QR content digests in distinct comparison namespaces so equal-looking strings cannot authorize another identity class. Specific owns comparison keys; Same owns the actual session-origin key, not the target profile. Never use SavedTag’s record-name hash as the NFC comparison key. Two identical QR payloads remain the same key; static identifiers can be copied, so this is key matching, not hardware authenticity.

The current code reads only `webpageURL` and profile UUID, rather than inspecting available NDEF data or parsing identity metadata. The audit records that current-code boundary, not an inability of iOS to expose NDEF content. The human-selected path suffix is binding; do not substitute a query parameter. Existing `NavigationManager` resolves the first two path segments, so verify older-reader and associated-domain matching for the new suffix in #521 rather than assuming a new endpoint is needed. App-written tag writing, QR generation, in-app identity readers, background parser, storage and private session sync must all use the same canonical key. A reader/NDEF error is a failed scan with a retry prompt, never authorization to fall back to UID or enroll the wrong identity. A successful read finding no NDEF or non-profile content may use the raw UID fallback; a successfully read legacy no-ID profile payload requires the explicit migration decision below.

A Timer duration must be an integer within existing `DeviceActivityLimits.minimumIntervalMinutes...maximumTimerMinutes` (currently 15...1439 minutes). Reject missing, malformed, zero, negative or out-of-range values rather than clamping or using the legacy decoder's silent 15-minute default. The OS-accepted deadline, not a displayed configured duration, describes an active countdown. The proposed repair policy for pre-existing missing/invalid durations is gated below; it does not silently create a default duration.

The profile owns an “allow changing before start” option (final label/copy gated). With it off, every start uses the saved duration. With it on, an interactive manual start offers adjustment before registration; cancelling starts no session. Child mode, including a locked profile, may use that adjustment without an additional unlock. Editing the saved duration/option remains subject to the existing profile edit lock. Background, tag and scheduled starts always use the saved duration, even when the option is on. Profile-link entry is a background-style start for duration purposes; transport through the app does not automatically make it an interactive manual start.

The proposed adjusted duration affects only that session; saving it back is an open human choice. The adjustment must pass the same range and registration checks. The existing Shortcut Duration parameter cannot override the saved duration under the background-start ruling. Recommend a descriptive refusal when an old Shortcut supplies that parameter, with instructions to edit the profile duration or remove the parameter, rather than silently claiming an override was used; final error copy belongs to G2. No Shortcut Duration exception may bypass R2/R4 or dispatch a V1 strategy.

## Every start × stop combination

Each cell assumes the start is enabled and the stop has valid required data. **Yes** means independent of origin, **Own** means a registered countdown owned by this session, **Same** means matching this session's captured key, and **—** means this stop is inapplicable. A row containing — needs another applicable configured stop. Any/Specific NFC and QR starts each use the row for their tag type. NFC/QR None is inapplicable in every row.

| Session origin | Manual | Timer | NFC Any | NFC Specific | NFC Same | QR Any | QR Specific | QR Same | Schedule |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Manual | Yes | Own | Yes | Yes | — | Yes | Yes | — | Yes |
| Identified NFC scan or typed NFC link | Yes | Own | Yes | Yes | Same | Yes | Yes | — | Yes |
| Identified QR scan or typed QR link | Yes | Own | Yes | Yes | — | Yes | Yes | Same | Yes |
| Shortcut (saved duration) | Yes | Own | Yes | Yes | — | Yes | Yes | — | Yes |
| Legacy profile link without identifier | Yes | Own | Yes | Yes | Any* | Yes | Yes | Any* | Yes |
| Scheduled callback | Yes | Own | Yes | Yes | — | Yes | Yes | — | Yes |

**Any*** is the human-approved per-session exception: each configured Same kind behaves as Any of that type for a session started from an unidentified legacy link. Record that origin explicitly, preserve it on mirrors, and clear it on completion/replacement. It never weakens Specific, affects a typed identified origin, or turns an ordinary non-tag start into Any. Specific still requires a configured matching key presented later; the unidentified link itself cannot satisfy Specific.

A same-account mirror preserves the authoritative origin and typed comparison start key, so it uses the originating row for Same. It adopts the existing accepted deadline; adoption is not a new local start and must not register another countdown. Start identity must be replaced on a new session and cleared on completion so old scans cannot authorize a replacement. Unknown/missing identity in older session records never becomes Any without an authoritative explicit legacy-link origin; see compatibility gate below.

## Save, duplication, sync and every-start checks (#493, #511–#513, #520)

Offer all stop choices, including Same, regardless of selected starts. Explain Same's session-specific meaning. Changing starts must not hide, clear or rewrite stops or their owned data. Save can be refused with a descriptive error; refusing Save is different from deleting the user's selection.

Save and duplication require nonempty, well-formed stops and R4 coverage. If Same NFC is selected and any ordinary non-NFC start (Manual, Shortcut, Schedule or identified QR start) is enabled, require an additional stop that does not rely on Same. Apply the symmetric QR rule. NFC+QR starts with only their two Same kinds are insufficient under R4’s explicit non-Same requirement. A selected Same with no corresponding identified origin may remain alongside a valid non-Same stop, with an explanation; do not erase it.

Link starts are unchanged. Identified typed links have their encoded tag origin and use the matching row; unidentified legacy links use the latest explicit Any-session exception, so do not reject a Same-only legacy-link start merely because no opaque key was captured. Check actual incoming typed origin at every start: an opposite-type link still needs an applicable stop and cannot fabricate a matching Same. The single enabled Link start flag permits both typed NFC and typed QR origins (the editor can generate either). Therefore, for R4 Save/duplication coverage it counts as both tag types: a Link-start profile with any Same kind needs a non-Same stop, just as an NFC+QR-start profile does. Do not add a new per-profile type flag to evade this rule. An actual old no-ID Link start keeps the explicitly approved per-session Any exception, including existing Same-only configurations; the runtime check validates its actual effective stops rather than rejecting that authorized legacy case for editor coverage. No V1 strategy projection decides it.

Check those invariants and actual-origin applicability at **every boundary that originates a session**, using current decoded/normalized configuration, not just the editor's last result: Home/manual, both in-app scan types, Shortcut (including an obsolete Duration argument), profile link (including R10 switching), monitor scheduled start, and any direct/shared session-creation path. Specific stop keys never need to equal start keys. Timer counts through real registration; Schedule counts independently of starts. Remove `hasUsableStop` and its credential-pair/background-veto rules.

For ordinary starts, runtime rejects any configuration violating R4 coverage; the explicit no-ID legacy-Link exception above is evaluated with its authorized effective Same-to-Any stops. Perform validation before restrictions, session insertion/publication, stopping an existing session or other takeover effects. Malformed/missing/unsupported stop data refuses a new start with a useful error; monitor/headless failures use existing user-visible error/notification mechanisms. Do not add an implicit manual exit or treat emergency unblock as a configured stop. Preserve existing selection, Screen Time, mode, edit-lock and geofence authorization requirements where applicable; no geofence or background setting may veto configured Timer/Schedule expiry.

Incoming private sync can retain an invalid profile for repair; invalid data must not gain runtime permission or silently mutate into a permissive configuration. An authoritative active session restored/adopted from shared/private state is handled separately: configuration validation is not authority to discard its blocking state or fabricate a fresh start. Compatibility handling for missing mirrored Same identity remains a gate below.

For #520, normalize each legacy tag flag triplet once at decoding/ingestion: **Specific > Same > Any > None**, preserving the existing restrictive precedence, independently for NFC and QR. Missing Specific keys produce an invalid Specific stop; never fall through to Any. New canonical data stores only one enum/value per type; a recognized canonical value takes precedence over legacy flags, while unknown/malformed canonical values invalidate the configuration rather than falling back. Normalize existing storage, incoming records and snapshots consistently, then apply required-data/R4 checks. No OR interpretation of contradictory flags, no start-dependent normalization, and no new strategy hierarchy. Wire compatibility with older readers must be explicit in #520's design; derived legacy wire fields, if needed, cannot become V2 runtime authority.

## Countdown establishment, expiry and cleanup (#509–#510)

Prepare a session identity and validated duration, register exactly one countdown, and obtain its accepted deadline **before committing or exposing a new active session or restrictions**. App and monitor originating paths must share the same contract, despite being separate processes. Reuse the existing registrar/timer activity machinery after removing V1 behaviour; do not instantiate NFC/QR/Shortcut timer strategies to create V2 sessions.

If registration fails, refuse start, surface the error, and leave any existing session/restrictions untouched. This applies even when another stop is also enabled. If subsequent persistence/publication fails, cancel the provisional countdown and report failure; no stray activity may create a session or apply restrictions. Recheck session ownership before committing any approved takeover; a race cleans up the candidate timer rather than ending the winner. An OS start callback alone never creates a timer session or activates restrictions for a missing session.

Expiry verifies the exact session ownership and accepted deadline, and ends only that session with the existing expected-session identity guard. A callback for a missing/replaced session, including a later session of the same profile, is a no-op; an early callback cannot end before the accepted deadline. Duplicate completion is idempotent. An authorized early stop, deletion or takeover cancels only the departing session's timer. Publish/clear timing and scan identity consistently across local, shared and private sync representations. A mirror adopts timing and propagates a matching stop through the existing authoritative completion flow, not a second timer registration.

Do not promise precise OS delivery. Registration success establishes the countdown; extension/device acceptance must demonstrate actual expiry separately from pure/unit tests.

## Independent schedule recurrences (#515–#517)

A start schedule and a stop schedule each own their weekday/time recurrence and registration. Reuse the existing stop-only activity; registering/removing it cannot depend on successful start registration. A V2 start activity's artificial interval end does nothing. OS minimum interval requirements constrain each internal activity window, not the gap between product start and stop events.

Monday 09:00 start / Friday 17:00 stop must not stop on Monday at 17:00. Monday 09:00 / Friday 09:00 is valid; equal clock times on disjoint weekdays are different moments. Monday 09:00 / Friday 09:10 is also valid; even same-day distinct events less than 15 minutes apart are permitted when internal registrations meet OS requirements.

Refuse Save for overlapping start/stop occurrences: both recurrences enabled, at least one common weekday, and equal hour/minute under the same calendar convention. Runtime independently checks stop due before admitting start, regardless of callback order, so no replacement session survives a same-occurrence collision. A start callback cannot resurrect a session already stopped for that occurrence. Retain existing stopped-occurrence suppression; do not use it as foreground catch-up. Scheduled-start takeover keeps its existing outgoing-profile Manual-stop and permitting-geofence requirement, with the skipped-start notification otherwise; only the removed background veto disappears. Incoming R2/R3/R6 validation still occurs before any takeover effect.

R7 removes foreground/app-launch/configuration-refresh creation of sessions for earlier scheduled starts. Refresh may register future activities, reconcile authoritative existing sessions and reminders, but must not call the scheduled creator because a historical window looks active. Actual OS callbacks are best effort under the later human ruling: accept a valid enabled registered start occurrence even if delivered late, subject to ownership, already-handled occurrence and stop-wins checks. Do not infer a scheduled start merely from the current clock. No arbitrary grace period is introduced. Handling a delayed start after its independently due stop is a human gate recommendation below.

Scheduled stop callbacks check their own recurrence and matching active profile/session, regardless of start modality. They never consult Disable Background Stops, a V1 combined schedule or the artificial end of a start activity. R5 guarantees application acceptance of a configured due stop; it does not guarantee iOS executes at an exact wall-clock instant.

Migration may convert actual V1 data once. After migration, V2 fields alone govern registration, callback decisions, cleanup and display; retained legacy schedule/blob/strategy columns cannot restart or stop a migrated profile. Removing a V2 schedule removes its obsolete activities. Genuine unmigrated profiles, including deferred migration while active, keep narrowly bounded compatibility handling until the human resolves #59. Do not delete legacy data as a prerequisite to independence.

## One tag concept and switching (#521, R10 decided)

Remove the separate Link stop choice and its `deepLink` stop authority from new V2 configuration, editor, matcher, status and tests. In-app readers parse app-written link **identity**, preserving an opaque signature; they do not dispatch its profile target as a new command. A signature scan may stop A under A’s configured kind, and never implicitly starts B. A background/direct Link command names B and follows the switch flow below. Both routes match the same canonical key when identity is present.

Link starts and profile-URL targeting remain configured as before. When the event has a matching typed identity, Any/Specific/Same can all match it in either path. The earlier R10 required-in-app-scan wording applies when a command lacks or does not supply A’s required signature: prompt for the configured key rather than bypassing it. A successful in-app confirmation is A’s stop proof, not automatically B’s initiating key.

New profiles cannot select Link stop. Existing inactive Link-only profiles retain repairable data, but refuse new starts if no real valid stop remains and require one at the next edit; do not auto-add Any. **The human-approved transition for already-active Link-only sessions** preserves that exact pre-upgrade session’s legacy Link exit, locally and on mirrors, until completion. It cannot authorize a replacement/new session; clear the grandfathered permission on completion and enforce new V2 rules thereafter. Restoring authoritative active state does not silently delete restrictions or its last exit.
With A active and an event targeting B, first validate B's enabled start, selection, well-formed/applicable stops and saved timer. Apply A's tag stop kind for the presented modality:

| A's tag stop kind | Required switch result |
| --- | --- |
| Any of that type | Stop A and start eligible B; no separate link-stop permission. Legacy no-ID commands may satisfy Any of either type. |
| Specific or Same of that type | Match a valid presented opaque key; if no matching key is available, ask for an in-app scan of A’s required key first. Keep A running and B pending until matching proof exists. A cancelled/failed/wrong-key scan leaves A running and B unstarted. Preserve B as target through this confirmation; the confirmation scan authorizes A's stop and is not automatically B's initiating key. |
| None of that type | Keep A running and do not start B, even if A has Manual or another tag type enabled. |

Prepare B's countdown and recheck exact A ownership before ending A. If B validation/registration fails or A changes during the prompt, do not stop A; cancel any candidate timer and abandon/re-evaluate the stale pending switch. After an authorized switch, clean up A's timer without cancelling B's. Retain existing applicable geofence/mode authorization; remove the background veto and V1 force-start bypass. A scan without a profile target may stop A under its configured kind but never invents B. A typed link uses only that type: NFC accepts Any NFC, QR accepts Any QR. An old untyped link may satisfy either Any NFC or Any QR, as the human explicitly ruled. If neither Any is configured but a relevant Specific/Same stop exists, prompt for its required in-app signature; if both types offer such a stop, offer the existing scan picker and retain B as target. If neither type has a tag stop, leave A running. A direct Link command with a valid encoded key supplies that logical signature; a UUID alone never supplies a UID/digest. Raw UID matching remains available only through a real in-app scan of non-app-written NFC. B’s identified Link origin captures its own opaque key; an unidentified legacy Link origin records the approved Same-to-Any session exception instead of adding an identifying start scan. The same-target A link stops only through its tag condition, with the same proof/prompt requirements; it must not create an immediate replacement session.

## Background stops and presentation (#514, #518–#519)

Remove Disable Background Stops UI, setting authority, runtime veto and contrary tests. Existing stored/synced flags are ignored, including on schedule, tag/link and Shortcut stop paths. Historical decode-only columns can remain while compatibility requires them; they are not a user setting. Each stop request still requires the active matching session and its configured condition: Shortcut uses Manual, tag/link delivery uses R10 and the relevant NFC/QR kind, Schedule uses its own recurrence, and Timer uses session-owned expiry.

Render separate V2 start and stop summaries on cards, with existing labels/icons; use V1 strategy labels only for genuinely unmigrated profiles. Schedule presentation must keep distinct weekday sets and times intelligible rather than merging them into a daily range. Timer plus Schedule is valid; warn only on actual invalid data or registration failure. Configured duration describes configuration; an active countdown uses the accepted deadline, including approved interactive adjustments and mirrored timing. Align card, widget and Shortcut status with those facts. Stop need not offer immediate manual exit for a timer-only profile whose countdown is actually registered.
